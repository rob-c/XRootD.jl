# Plan 03: File I/O Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The public `File` API with 0.2.x-verbatim semantics — gated on
`test/legacy/testFile.jl` passing unmodified against a real server — plus the
v5 parity additions: `sync`, vector reads/writes (`readv`/`writev`), and
paged I/O with per-page CRC32c (`pgread`/`pgwrite`).

**Architecture:** Spec phase 4. `File` is Layer-3 sugar over the Session
roundtrip and the Wire file codecs (open/read/write/close landed in plan 02
for `copy`). New wire work: readv/writev vector framing and the `kXR_status`
response framing for paged I/O. The `kXR_status` frame carries page data
BEYOND its header `dlen` (ops_file_pg.c) — the Session reader task learns to
read that trailer so the mux stays intact.

**Tech Stack:** stdlib `CRC32c` (hardware-accelerated) for page checksums.

## Global Constraints

Plans 01–02 constraints, plus:

- `test/legacy/testFile.jl` runs VERBATIM. That pins these 0.2.x behaviors:
  `File(url, flags=0, mode=0) -> File | nothing`; `read(f, size, offset=0)`
  does NOT advance the cursor (offset≠0 sets it); `readline` keeps the
  trailing `"\n"` except on the final line and returns `""` at EOF with an
  OK status; `eof` compares the cursor to the size captured at open;
  `write(f, data::String, offset=0)`; `unsafe_read(f, ptr, size, offset=0)
  -> (st, nbytes)`; `close` resets state; `stat(f)` is fhandle-based.
- A `File(url)` open with no access bits set opens read-only
  (`kXR_open_read`), matching what the 0.2.x binding got from XrdCl.
- pgread/pgwrite framing (ops_file_pg.c, the ground truth):
  one status frame = `ServerResponseHdr{status=kXR_status, dlen=24}` +
  24-byte body `{crc32c[4], streamID[2], requestid[1], resptype[1],
  reserved[4], pgdlen[4], offset[8]}`; the crc32c covers body bytes 5:24;
  `resptype` 0=Final 1=Partial; `pgdlen` bytes of page data FOLLOW the body
  (outside hdr.dlen). Page units: `[crc32c_be 4][data ≤4096]`, aligned to
  the FILE offset (short first page).
- readv/writev vector entries are 16 bytes: `fhandle[4] + rlen/wlen(i32) +
  offset(i64)` (readahead_list/write_list). The readv response body is a
  sequence of `readahead_list` echo + data per segment.
- Opcodes from opcodes.h (already in Wire): readv 3025, pgwrite 3026,
  pgread 3030, writev 3031.
